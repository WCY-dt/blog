# 设计配方

下列为可轮换的设计资源，不是必须逐项执行的清单。延续已认可的“清楚的单个物体、活泼油画笔触、安静的浅色几何背景”。

## 从文章提炼单个主体

| 文章或主题 | 可选主体 | 取舍依据 |
| --- | --- | --- |
| 银行卡交易剖析 | 一张蓝色芯片银行卡 | 直接对应交易媒介；不加入 POS 机和现金 |
| 企鹅岛上的鱼指导 | 一条用尾鳍直立的鱼 | 对应主人公；安静、若有所思，保留鱼的解剖特征 |
| 深入 Java 系列 | 一只装有咖啡的陶瓷杯 | 可覆盖系列，保留杯把和少量蒸汽，无杯碟 |
| 树莓派安装使用 | 一块树莓派开发板 | 明确对应硬件；主要接口可识别，不追求针脚级制图 |
| 概率、随机性 | 一颗骰子 | 具体且直观；避免骰子堆和公式 |
| 毕业典礼随想 | 一顶学士帽 | 先确认全文重点适合该物体，不加毕业人群 |
| 消息队列 | 一个信箱 | 属于隐喻，应读文后确认；不堆砌箭头和消息气泡 |

这些是候选，不是标题到物体的机械映射。用户指定的主体优先。不要把“拟人化的鱼”推广为所有物品都要长眼睛；也不要因提到技术品牌就必须复刻其标志。

## 几何背景库

每张通常只采用一种主纹样。几何变化来自色块和线条本身，不加入写实地面、天空、岛屿、建筑或装饰物。

| 纹样 | 构造要求 | 使用建议 |
| --- | --- | --- |
| 中心放射线／扇形色块 | 从画面正中心汇聚，宽而均匀 | 突出扁平主体；色差小，避免海报爆炸效果 |
| 等边三角形密铺 | 连续铺满、大小一致，2–3 种浅色 | 适合圆润主体，与曲面形成温和对照 |
| 整齐正弦波色带 | 横向、等间距、同振幅和波长，宽带而非细线 | 适合动物和竖向主体；不要画成真实水面 |
| 同心圆宽色环 | 圆心与画面中心重合，宽环交替填色 | 适合小巧物体；避免细线、密集靶心和光晕 |
| 宽幅斜条纹 | 平行、同宽或有规律交替 | 适合轮廓简单的物体；斜率不必和主体完全一致 |
| 菱形色块密铺 | 规整的斜向大菱形交替填浅色，无描边 | 适合块状主体；不使用轮廓网格 |
| 圆点阵列 | 同尺寸、等间隔的小圆点 | 适合较复杂的主体；稀疏分布，勿作噪点 |
| 六边形密铺 | 均匀的大块浅色六边形，无描边 | 适合技术类物件；不叠加电路纹理 |
| 重复半圆／拱形 | 同尺寸、规律排列 | 增加柔和秩序；不加入窗框等具象细节 |
| 宽幅阶梯色带 | 宽实心直角折带，间距均匀 | 给简洁主体增加节奏；避免细折线和复杂迷宫 |

主体纹理越丰富，背景越应疏朗。背景应完全不透明地覆盖整个正方形，不只围在物体周围形成贴纸白边。不得存在细线纹样；约 200 像素缩略图中的宽带仍应有清楚的宽度，优先大色块交替铺排。

## 浅色配色池

色值是提示词中的近似色彩目标，不要求生图输出精确命中每个像素。

| 色系 | 底色参考 | 纹样参考 | 可搭配的主体色 |
| --- | --- | --- | --- |
| 杏色／奶油 | `#FFF1DA` | `#F7DDBB` | 钴蓝、青蓝 |

| 淡桃粉 | `#FBE7E3` | `#EDCDCA` | 深青、群青 |
| 浅柠檬黄 | `#FAF5D9` | `#EAE1B5` | 紫蓝、蓝灰 |

主体可以鲜明浓郁，背景始终保持明亮、低饱和、低对比。优先用冷暖差和明度差分离主体，避免依赖粗描边、发光轮廓或强烈投影。表中的主体色只是搭配示例，不是受限色板。

## 主体主色多样性

2026-09-26 用户指出主体反复集中在蓝、橙、金色，要求重画并丰富主体主色。此反馈优先于原样稿的配色惯性：保持画法，不固定配色。

批量设计时单独填写主体主色，覆盖适合题材的多个色系，例如玉绿储蓄罐、酒红学士帽、紫色梯子、银灰潜望镜、玫红毛线球、墨绿信箱、黑白羽毛的鸡。中性色主体同样能丰富整体，不必每件物体都五彩斑斓；一个物体通常以一个主色或自然色组合为主，辅以少量反光色。

品牌标志、真实物体的关键识别色优先保留，例如 Redis 经典标志的红色。靠其他可灵活配色的主体实现整组变化。不要把“不同主色”变成所有图都铺满互补色笔触；大量蓝色阴影和金色高光也可能淹没原定主色。

## 批量分配

先对独立文章和系列去重；系列为一个设计单元。查看首页或文章列表实际排序，优先让相邻的不同单元在背景色相或几何纹样上有所区别。同系列的连续重复属于正常识别线索，不应为消除重复而改图。

维护一份 Markdown、JSON 或项目已有格式的映射表，至少记录：

- `key`：稳定的文章标识或系列标识。
- `posts` / `series`：适用范围。
- `subject`：单个主体及必要姿态。
- `subject_palette`：主体的主色和辅助色，与背景分开记录。
- `palette` / `pattern`：背景色系和几何纹样。
- `file` / `prompt`：图片与实际提示词路径。每篇图片文件名与其 Markdown 文件名一致，只更换扩展名；同系列记录一个生成来源及多个同内容、不同文章文件名的副本。
- `status`：待生成、已生成、待修订或已确认。

默认在项目的开发资料目录维护映射；图片统一存入 `assets/post/covers/` 并采用文章 Markdown 同名规则。没有被用户确认的图片不要记成“已确认”。用户要求直接批量完成时可记录“已生成并检查”，不以等待确认阻断整个任务。
